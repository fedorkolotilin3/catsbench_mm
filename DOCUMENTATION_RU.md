## 1. Для чего нужен проект

CatSBench — исследовательский набор инструментов для задач энтропийного оптимального транспорта (EOT) и мостов Шрёдингера (SB) на дискретных пространствах.

Объект данных — вектор категорий. Например, при `D=2`, `S=50` точка имеет две целочисленные координаты из диапазона `0…49`. В изображениях категориями могут быть значения каналов пикселей или индексы кодовой книги VQGAN.

На уровне пользователя постановка выглядит так:

1. Есть исходное распределение `p0` и целевое распределение `p1`.
2. Нужно построить случайное преобразование исходного объекта в целевой.
3. Для динамического метода дополнительно интересует последовательность промежуточных состояний.
4. На синтетическом бенчмарке можно сравнить результат с доступным эталонным решением.

Совпадение итогового распределения с `p1` ещё не означает правильного переноса: метод может генерировать подходящие конечные объекты, игнорируя вход. Поэтому проект отдельно оценивает конечное распределение, условное преобразование и переходы процесса.

### Два способа использования

| Интерфейс | Что предоставляет | Когда выбирать |
|---|---|---|
| Python-пакет `catsbench` | Эталонный бенчмарк, выборки, траектории, метрики, сохранение и загрузка | Нужны данные и оценка собственного алгоритма |
| Репозиторий и команда `python -m src.run` | Обучение четырёх методов, готовые эксперименты, checkpoints, логирование | Нужно воспроизводить или менять исследовательские эксперименты |

`pip install catsbench` устанавливает только пакеты `catsbench` и `catsbench.*`. Каталоги `src.methods`, `src.data`, конфигурации и скрипты обучения в состав этого пакета по настройке сборки не входят.

## 4. Контракт данных

Обозначения в дальнейшем:

| Обозначение | Смысл |
|---|---|
| `B` | Число объектов в батче |
| `D` | Число категориальных координат объекта |
| `S` | Число категорий одной координаты |
| `N` | Значение `num_timesteps` |
| `K` | Число потенциалов `num_potentials` |

Основные формы:

| Объект | Форма | Тип и смысл |
|---|---|---|
| HD-выборка | `[B, D]` | `torch.long`, категории `0 <= x < S` |
| Конечный результат | Такая же, как вход | Категории целевого объекта |
| HD-траектория | `[N+2, B, D]` | Начало, промежуточные состояния, конец |
| Логиты переходов траектории | `[N+1, B, D, S]` | Последняя ось — возможные категории |
| Логиты одного перехода | `[B, D, S]` | Для каждого объекта и координаты |
| Raw image категории | Обычно `[B, 3, H, W]` | Целочисленные значения каналов |
| Декодированное изображение | `[B, 3, H, W]` | Float в `[0, 1]` |
| VQGAN-категории | `[B, L]` | Последовательность индексов кодовой книги |

**В этой реализации `N` означает `N+1` переходов и `N+2` состояний траектории.** Это важно при написании своего solver и вычислении KL.

Тензоры данных, времен, модели и метрик должны находиться на согласованном устройстве. Для NumPy используйте `tensor.detach().cpu().numpy()`.

Категории не следует автоматически интерпретировать как исходные непрерывные координаты. `continuous_to_discrete(...)` выполняет квантование по границам диапазона; это не взаимно однозначное преобразование.

## 5. Готовый эталонный бенчмарк: Python API

### Загрузка

```python
import torch
from catsbench import BenchmarkHD

torch.manual_seed(42)

bench = BenchmarkHD.from_pretrained(
    "gregkseno/catsbench",
    "hd_d2_s50_prior_gaussian_a0.02",
    init_benchmark=False,
    device="cpu",
)

print(bench.name, bench.dim, bench.num_categories, bench.device)
```

При первом обращении нужны доступ к Hugging Face и загрузка конфигурации и тензоров. Доступность удалённых файлов в рамках этого анализа не проверялась. Для работы с кэшированной копией существует `local_files_only=True`; для фиксации версии — `revision=...`; путь к кэшу задаётся через `cache_dir=...`.

`init_benchmark=False` пропускает случайное создание новых параметров и валидационной выборки: они восстанавливаются при загрузке. Референсный процесс при этом всё равно создаётся. После успешного `from_pretrained` доступны также парные выборки и траектории.

Не используйте `BenchmarkHD(config, init_benchmark=False)` как готовый новый бенчмарк: без последующей загрузки его буферы содержат неинициализированные значения.

### Выборки: три разных операции

```python
# Два независимых набора: совместно это p0(x0) * p1(x1).
x0 = bench.sample_input(128)
x1 = bench.sample_target(128)

# Эталонные связанные пары.
x0_paired, x1_paired = bench.sample_input_target(128)

# Эталонный перенос заданных входов, для обычного reverse=False.
assert not bench.reverse
y = bench.sample(x0)
```

Независимые `x0[i]` и `x1[i]` не задают правильную пару для supervised-регрессии. Парные данные следует получать отдельной операцией. `sample_target` генерирует новые конечные объекты через эталонный перенос; это не просто выбор строк из `target_dataset`.

### Справочник основных методов

| Вызов | Результат и назначение |
|---|---|
| `sample_input(B)` | Новые исходные объекты |
| `sample_target(B)` | Новые целевые объекты |
| `sample_input_target(B)` | Кортеж связанных эталонных выборок |
| `sample(x, use_onestep_sampling=True)` | Конечные объекты без построения всей траектории |
| `sample(x, use_onestep_sampling=False)` | Конечные объекты после последовательного процесса |
| `sample_trajectory(x, use_onestep_sampling=False, return_transitions=False)` | Траектория; при запросе переходов — кортеж `(trajectory, logits)` |
| `markov_sample(x_t, t, return_transitions=False)` | Один шаг; `t` — вектор времен `[B]` от `0` до `N` |
| `get_transition_logits(x_t, t)` | Логиты следующего состояния по координатам |
| `get_cum_transition_logits(x_start)` | Логиты конечных категорий по координатам для заданного начала |
| `plot(num_samples, num_trajectories, num_translations)` | Показывает распределения и, в прямом режиме, траектории |
| `save_pretrained(directory, subfolder=...)` | Сохраняет конфигурацию и тензоры |
| `from_pretrained(directory_or_repo, subfolder, ...)` | Загружает сохранённый бенчмарк |
| `push_to_hub(repo_id, subfolder=..., ...)` | Публикует бенчмарк в выбранном репозитории |

`get_cum_transition_logits` не возвращает таблицу по всем `S**D` совместным исходам. Не заменяйте эталонный `sample` независимым сэмплированием каждой координаты по этим логитам: так можно потерять зависимости между координатами.

### Траектории

```python
x0 = bench.sample_input(16)
trajectory, transition_logits = bench.sample_trajectory(
    x0,
    use_onestep_sampling=False,
    return_transitions=True,
)
print(trajectory.shape)        # [N+2, 16, D]
print(transition_logits.shape) # [N+1, 16, D, S]
```

`use_onestep_sampling=True` у `sample_trajectory` сначала выбирает конец, затем отдельно выбирает промежуточные состояния условно на концах. Этот режим не предоставляет `return_transitions=True`. Для оценки последовательной динамики используйте режим `False`: отдельные условные выборки промежуточных времен не следует автоматически считать совместной марковской траекторией.

### Обратный бенчмарк

`reverse=True` меняет местами публичные маргиналы и порядок элементов эталонной пары. Однако `sample`, `get_transition_logits` и динамический sampler в базовом классе не превращаются от этого в oracle обратного процесса.

Поэтому формула `bench.sample(bench.sample_input(B))` как перенос из публичного `p0` в публичное `p1` применима непосредственно к обычному `reverse=False`. Для обратного режима безопасный интерфейс эталонных данных — `sample_input_target`; встроенный callback оценивает связанные пары через C2ST и не использует прямые conditional/KL-оценки этого oracle.

## 6. Создание собственного бенчмарка

Минимальный полный пример с небольшой валидационной выборкой:

```python
import torch
from catsbench import BenchmarkHD, BenchmarkHDConfig

torch.manual_seed(42)
config = BenchmarkHDConfig(
    dim=2,
    input_shape=(2,),
    num_potentials=5,
    num_categories=50,
    radius=5.0,
    alpha=0.02,
    num_timesteps=15,
    num_skip_steps=8,
    prior_type="gaussian",
    benchmark_type="gaussian",
    input_distribution="gaussian",
    sample_quantize_range=(-3, 3),
    num_val_samples=256,
    init_batch_size=64,
    reverse=False,
    tau=1.0,
    params_dtype="float32",
)
bench = BenchmarkHD(config, init_benchmark=True, device="cpu")
```

Это создаёт новый случайный экземпляр, а не воспроизводит загруженный эталон из Hub. Для научного сравнения фиксируйте и сохраняйте сам экземпляр.

| Настройка | Что меняет пользователь |
|---|---|
| `dim`, `input_shape` | Размерность и форму объекта; для HD используйте `(dim,)` |
| `num_categories` | Размер категориального алфавита |
| `num_potentials` | Сложность параметризации эталона |
| `radius` | Размещение центров при Gaussian-инициализации |
| `input_distribution` | Исходную генерацию: `gaussian` или `uniform` |
| `sample_quantize_range` | Границы квантования исходных данных |
| `benchmark_type` | Инициализацию потенциала: `gaussian` или `uniform` |
| `prior_type`, `alpha` | Вид и параметр стохастичности референсного процесса |
| `num_timesteps`, `num_skip_steps` | Временную сетку и объединение базовых шагов |
| `num_val_samples` | Размер сохраняемого эталонного набора |
| `init_batch_size` | Размер батча при создании набора |
| `reverse` | Перестановку публичных маргиналов и пар |
| `tau` | Температуру категориального сэмплирования |
| `params_dtype`, `eps` | Численную точность и стабилизацию |

`input_distribution`, `benchmark_type` и `prior_type` — разные переключатели. Например, `prior_type="gaussian"` сам по себе не выбирает исходное распределение.

У Gaussian-инициализации в текущем коде есть таблица масштабов только для `D ∈ {2, 16, 64, 3072, 4096}`. Произвольную размерность нельзя считать поддержанной этим вариантом создания без изменения кода. Для `uniform` исходные непрерывные значения генерируются в `[-3, 3]`, даже если границы квантования заданы иначе.

### Изменение временной сетки загруженного экземпляра

Разрешён runtime override `num_timesteps`. Совместимость проверяется по условию:

```text
total = (saved_num_timesteps + 1) * saved_num_skip_steps
total % (new_num_timesteps + 1) == 0
new_num_skip_steps = total // (new_num_timesteps + 1)
```

Например, `(15+1)*8 = (63+1)*2 = 128`. При совместимом изменении сохраняется полная длительность базового референсного процесса.

Загруженный `config.json` авторитетен: передать новую `config=` поверх существующей конфигурации запрещено загрузчиком. `bench.config` хранит исходную конфигурацию, а эффективные `bench.num_timesteps` и `bench.num_skip_steps` могут отличаться после override; записывайте override отдельно при воспроизведении.

### Сохранение и повторная загрузка

```python
bench.save_pretrained("./my_benchmarks", subfolder=bench.name)
restored = BenchmarkHD.from_pretrained(
    "./my_benchmarks", bench.name, init_benchmark=False,
)
```

Основные файлы — `config.json` и `model.safetensors`. При загрузке из Hub также предусмотрен fallback к PyTorch weights. Аргумент `subfolder` в `from_pretrained` обязателен; если сохранено непосредственно в корень каталога, можно передать пустую строку.

Сохранение эталона и сохранение обученного solver — разные операции: первая использует `save_pretrained`, вторая — Lightning `.ckpt`.

## 7. Оценка собственного метода

Для базовой оценки достаточно предоставить операцию:

```python
pred_x1 = solver.sample(x0)
```

Она должна возвращать категориальные объекты той же формы, на согласованном устройстве. Для conditional-метрик solver должен уметь генерировать много результатов одного входа.

### Доступные метрики

| Метрика | Что оценивает | Как трактовать |
|---|---|---|
| `ShapeScore` | Совпадение одномерных распределений отдельных координат | Больше лучше; стандартный score равен `1 - TV` |
| `TrendScore` | Совпадение двумерных распределений пар разных координат | Больше лучше; требует `D >= 2` |
| Conditional Shape/Trend | То же при фиксированном входе | Проверяет условный перенос |
| `ClassifierTwoSampleTest` | Различимость двух наборов классификатором | Здесь score = `1 - 2*abs(AUROC-0.5)`; больше лучше |
| `TrajectoryKLDivergence` | Расхождение категориальных переходов на выбранных состояниях | Меньше лучше; ноль при совпадении |

Shape/Trend не проверяют полное совместное распределение произвольной размерности: совпадение всех одномерных и парных маргиналов само по себе недостаточно для этого.

### Конечные распределения

Пример ниже предполагает, что `bench` и ваш `solver` уже созданы:

```python
from catsbench.metrics import ShapeScore, TrendScore

shape = ShapeScore(bench.dim, bench.num_categories).to(bench.device)
trend = TrendScore(bench.dim, bench.num_categories).to(bench.device)

x0 = bench.sample_input(1024)
real_x1 = bench.sample_target(1024)
pred_x1 = solver.sample(x0)

shape.update(real_x1, pred_x1)
trend.update(real_x1, pred_x1)
print({"shape": shape.compute().item(), "trend": trend.compute().item()})
shape.reset()
trend.reset()
```

Два аргумента Shape/Trend должны быть целочисленными непустыми тензорами одинаковой формы `[B,D]` с категориями в пределах алфавита.

У `conditional=False` вызовы `update` накапливают гистограммы всего набора; финальная оценка делается в `compute`. `reduction="none"` позволяет получить значения по координатам или парам координат. У Trend диагональные элементы не несут полезного сравнения; среднее берётся по внедиагональным парам.

### Условные распределения

```python
assert not bench.reverse
conditional = ShapeScore(
    bench.dim, bench.num_categories, conditional=True,
).to(bench.device)

for start in bench.sample_input(8):
    repeated = start.unsqueeze(0).expand(1000, -1)
    conditional.update(bench.sample(repeated), solver.sample(repeated))

print(conditional.compute().item())
```

Здесь **один `update` соответствует одному фиксированному входу**. Метрика не группирует разные входы сама. Если передать обычный батч разных начал, смысл conditional-оценки будет потерян.

Параметр `adjusted=True` у Shape/Trend включает поправку на различие конечных эмпирических выборок, использующую нормальную аппроксимацию. По умолчанию в библиотеке и HD callback стоит `False`; явно записывайте этот параметр при сравнении результатов. Trend хранит таблицы порядка `D²*S²`, поэтому размерность и число категорий существенно влияют на память.

### C2ST

Интерфейс: `update(real_data, pred_data, train=True)` обучает внутренний классификатор, `train=False` накапливает тестовые предсказания, `compute()` возвращает score. `reset()` также переинициализирует классификатор.

Нужны отдельные обучающие и оценочные примеры. Если тестовых обновлений не было, реализация возвращает служебное значение `-1.2345`, а не осмысленную оценку качества. При оценке сопряжения callback объединяет начало и конец в `[B, 2*D]`.

### Динамические метрики и время

Для них solver дополнительно предоставляет:

```python
trajectory, logits = solver.sample_trajectory(x0, return_transitions=True)
logits_at_states = solver.get_transition_logits(states, timesteps)
```

Forward KL оценивается на состояниях эталонной траектории: сравниваются эталонные переходы и переходы solver **в этих же состояниях**. Reverse KL — на состояниях solver. Сравнивать два массива логитов, полученные на разных траекториях, без повторного вычисления на общих состояниях неправильно.

`TrajectoryKLDivergence(dim, num_timesteps, logits=True)` принимает одинаковые формы минимум с тремя осями и нормализует последнюю ось через `log_softmax`. В режиме `logits=False` ожидаются вероятности.

Существенный нюанс текущей реализации: `compute()` умножает среднюю категориальную KL на `D * num_timesteps`, тогда как траектории содержат `N+1` переходов. Встроенный callback передаёт `N`. Для воспроизведения проектных чисел сохраняйте эту конвенцию; если нужен именно масштаб суммы по всем переходам, отдельно согласуйте множитель. Не меняйте его незаметно между экспериментами.

У CSBM/AlphaCSBM модельное время идёт от `N+1` к `1`, а у эталонного интерфейса — от `0` к `N`. HD callback учитывает это через `t_model = N+1-t_benchmark`.

## 8. Готовые методы обучения

| Метод и имя пресета | Пользовательская характеристика | Основные настройки |
|---|---|---|
| `DLightSB`, `dlight_sb` | Обучаемый перенос через параметризованный потенциал; отдельная denoiser-сеть в пресетах не используется | `num_potentials`, `distr_init`, optimizer, entropy-параметры |
| `DLightSB_M`, `dlight_sb_m` | Вариант с matching-обучением | Дополнительно KL/MSE coefficients и minibatch coupling |
| `CSBM`, `csbm` | Два denoiser-направления; обучение направлений чередуется | Модель, EMA, число первых итераций, KL/CE/MSE loss |
| `AlphaCSBM`, `alpha_csbm` | Оба направления обновляются внутри процесса обучения каждой эпохи | Модель, EMA, KL/CE/MSE loss |

Общий базовый интерфейс находится в `BaseMethod`: `sample` и `sample_trajectory`. Все четыре реализации также имеют операции работы с переходами.

У CSBM и AlphaCSBM можно явно задавать `fb="forward"` или `fb="backward"` при сэмплировании. У CSBM выбор по умолчанию зависит от текущей итерации; для самостоятельного inference задавайте направление явно. У AlphaCSBM по умолчанию используется `forward`.

`use_mini_batch` включает подбор сопряжения внутри батча через OT-утилиту; это алгоритмический параметр, а не размер батча. `argmax_mode` в denoiser-методах делает конечный шаг детерминированным по максимуму логитов. `tau` меняет случайность генерации. `num_first_iterations` относится к схеме обучения метода и не заменяет `trainer.max_epochs`.

### Модели

| Конфигурация | Модель | Вход и выход |
|---|---|---|
| `denoiser_mlp` | `DenoiserMLP` | Категориальные векторы и время → логиты категорий |
| `denoiser_image` | `UNet` | Изображения в категориях и время → логиты по пикселям/каналам |
| `latent_transformer` | `LatentTransformer` | Последовательность VQGAN-кодов и время → логиты кодов |

## 12. Результаты эксперимента и логирование

Обычный каталог запуска:

```text
logs/runs/<experiment>/<seed>/<date_time>/
├── .hydra/            # сохранённые Hydra-настройки при штатном запуске
├── train.log / test.log
├── logger_id          # создаётся при наличии конфигурации logger
└── checkpoints/
    ├── epoch_000.ckpt
    ├── ...
    └── last.ckpt
```

Checkpoint callback сохраняет все эпохи (`save_top_k=-1`) и последний checkpoint. Он не выбирает «лучшую» модель по метрике (`monitor=null`).

Для локального пути вида `<run>/checkpoints/*.ckpt` Hydra повторно использует `<run>`. W&B/Comet идентифицируются через `logger_id`; TensorBoard использует фиксированную версию `train` в каталоге логгера.

Метрики HD получают имена наподобие `val/shape_score_forward`, `test/cond_trend_score_forward`, `test/forward_kl_div_forward`. Суффикс направления важен для двунаправленных методов.

### Метрики изображений

| Метрика | Что сравнивается в коде | Когда вычисляется |
|---|---|---|
| FID | Предсказанное распределение и целевые изображения | Validation и test при подключённом image callback |
| MSE | Предсказанное изображение и **исходное** изображение | Validation и test |
| LPIPS | Предсказанное изображение и **исходное** изображение | Test |
| CMMD | CLIP-признаки предсказанных и целевых изображений | Test |

То есть MSE/LPIPS здесь характеризуют изменение относительно входа, а не ошибку реконструкции парного целевого изображения. FID/CMMD оценивают распределение результата. Для этих метрик могут потребоваться дополнительные скачивания весов Inception, LPIPS/CLIP. Image callback пропускает backward-направление.

Графики встроенных callbacks отправляются в logger. HD plotter поддерживает W&B и Comet, но не TensorBoard. Toy и image plotters поддерживают также TensorBoard. Простой `logger=null` недостаточен, если оставить любой из этих plotters включённым. Автоматическое сохранение всех графиков в PNG и сводной таблицы CSV этими callbacks не предусмотрено.

| `p1_paired.npy` | Концы тех же пар; соответствие по индексу |

Повторный запуск пишет в те же имена и заменяет существующие файлы. Для другого экземпляра или seed выбирайте отдельный `--out-dir`. Скрипт не сохраняет manifest с конфигурацией, версией и seed.

В текущей папке есть все четыре файла по 160 128 байт. Их содержимое и точное происхождение не проверялись; размер сам по себе не подтверждает параметры генерации.

### Две особенности скрипта

1. `--seed` вызывает только `np.random.seed`, хотя генерация бенчмарка использует PyTorch. Он не обеспечивает воспроизводимость выборки. Для воспроизводимого экспорта используйте Python API с `torch.manual_seed` и записывайте параметры.
2. При `--paired` скрипт ставит `init_benchmark=True`. Комментарий о необходимости этого для парных данных расходится с библиотекой: после успешного `from_pretrained(..., init_benchmark=False)` эталонные пары также доступны. Текущий вариант может зря сначала создавать данные, которые затем заменятся загружаемыми.

`testing.ipynb` читает `.npy`, строит 2D heatmap, гистограммы координат и стрелки парного переноса. Это просмотр данных, а не автоматический тест алгоритма. Оценка `S` по максимальной категории в конечной выборке может недооценить размер алфавита; действительное `S` берите из конфигурации эталона.

## 14. Ноутбуки и кластерные скрипты

`benchmark_usage.ipynb` — основной интерактивный маршрут: создать benchmark → получить выборки и траектории → вызвать метрики → сохранить/загрузить → при необходимости опубликовать. В ноутбуке есть условные dummy predictions; они иллюстрируют интерфейс и не являются обученным методом.

Он получает список бенчмарков из Hub, оценивает их и формирует pandas DataFrame. Это может быть длительный сетевой/GPU-прогон; просмотр ноутбука и выполнение всех ячеек — разные действия.

## 15. Интерфейсы для расширения

### Подключить свой solver только к бенчмарку

Начните с `sample(x0)`, согласовав формы, категории и устройство. Для Shape/Trend не нужен Lightning, Hydra или знание внутреннего представления потенциалов. Добавьте повторные выборки одного входа для conditional-оценки, затем — API переходов для динамической оценки.

### Встроить solver в конвейер обучения

Наследуйте `src.methods.BaseMethod`, реализуйте Lightning training/validation/test hooks и создайте конфиг `configs/method/<name>.yaml`, затем согласованный experiment preset. Встроенные callbacks ожидают выход шага с ключом `"batch"`, содержащим `Batch`, а не только scalar loss.

Для inference из Lightning checkpoint универсального отдельного CLI в `src.run` нет: доступны только `train` и `test`. Самостоятельная загрузка метода должна восстанавливать его архитектуру, prior и специфические checkpoint-состояния; один `state_dict` не следует считать полной заменой процедуры восстановления обучения.

### Подключить свои данные

Создайте DataModule с train/val/test loaders и операцией после передачи батча на устройство. Общий контейнер:

```python
from src.data.batch import Batch

batch = Batch(
    encoded=(x0_categories, x1_categories),
    raw=(x0_images_or_none, x1_images_or_none),
)
```

При распаковке `x0, x1 = batch` возвращаются `encoded`-данные. `raw` нужен прежде всего image-метрикам и визуализации.

`CoupleDataset` объединяет наборы по индексам с циклическим повторением меньшего; он не вычисляет истинное сопряжение. `RepeatedDataset` задаёт виртуальную длину; `SampledCoupleDataset` генерирует свежие независимые маргиналы.

### Подключить новый image codec

Реализуйте `BaseCodec`:

```python
cats = codec.encode_to_cats(images)  # изображения [0,1] → категории
images = codec.decode_to_image(cats) # категории → изображения [0,1]
```

DataModule переключает `train_data_mode` и `eval_data_mode` между `raw` и `encoded`. В режиме `encoded` он доверяет входным категориям и не кодирует их повторно. VQGANCodec ориентирован на поставляемую конфигурацию; замена кодовой книги/геометрии требует проверки совместимости decode.

### Использовать референсный процесс отдельно

`catsbench.prior.Prior` предоставляет `sample_bridge(x_start, x_end, t)`, `bridge_logits(...)`, `extract(...)`, `extract_last_cum_matrix(...)`, `posterior_logits(...)` и обратный вариант posterior. Это интерфейс для собственной дискретной динамики; при обычной работе с BenchmarkHD отдельно создавать Prior не нужно.

Фактически реализованы `gaussian` и `uniform`. Упоминание `von_mises` в комментарии YAML не означает поддержку: конструктор выдаёт `NotImplementedError`.

### Использовать LSE-умножение отдельно

```python
from catsbench.lse_matmul import lse_matmul

# a: [..., M, K], b: [..., K, P]
c = lse_matmul(a, b, implementation="any")  # [..., M, P]
```

Операция вычисляет `logsumexp_k(a[...,i,k] + b[...,k,j])`. Аргумент `eps>0` добавляет epsilon внутрь суммы перед логарифмом.

| Backend | Назначение |
|---|---|
| `cpu` | Точная reference reduction |
| `normalized` | Быстрый вариант для нормализованных логарифмов вероятностей |
| `any` | Стабилизированный вариант для произвольных логитов |
| `triton` | CUDA log-domain реализация; default, на CPU переключается на reference |

Настройка `implementation=` имеет приоритет над переменной среды:

```powershell
$env:LSE_BACKEND = "any"
```

Для работы с произвольными потенциалами не выбирайте `normalized` только ради скорости: его предназначение уже, чем у `any` и `triton`.

## 16. Ограничения, которые влияют на использование

| Ситуация | Что учитывать |
|---|---|
| `ModuleNotFoundError: hydra/lightning` | Пакет бенчмарка и окружение обучения устанавливаются отдельно |
| `Unsupported logger type` | HD plotter ожидает W&B/Comet; toy/image допускают также TensorBoard; без logger графические callbacks нужно отключить |
| Несовпадение metadata | Локальный data preset должен соответствовать сохранённому эталону |
| Ошибка совместимости `num_timesteps` | Проверьте делимость полной длительности на `N+1` |
| Произвольный Gaussian benchmark `D` | Встроенная таблица масштабов ограничивает поддержанные размерности |
| `ckpt_path=auto` ничего не находит | Учитываются выбранные experiment/seed и наличие `last.ckpt` |
| CelebA не запускается | Требуются внешние данные, quantized `.npy` и VQGAN checkpoint |
| TensorBoard есть, HD-графиков нет | Это ограничение HD plotter; toy/image поддерживают TensorBoard |
| Высокое время evaluation | Conditional sampling, траектории, KL и image-модели могут стоить существенно дороже одного training step |
| Валидация и test | В поставляемых DataModules `test_dataloader` использует `data_val`; отдельного независимого test split нет |
| `seed=0` в CLI | `src.run` проверяет seed по истинности, поэтому ноль пропускает вызов `L.seed_everything` |

В ноутбуке usage есть ошибочный комментарий, что transitions доступны при `use_onestep_sampling=True`; код требует `False`. Для high-dimensional `bench.plot` предусмотрена PCA; в standalone визуализации траекторий исходный фон не преобразуется PCA вместе с остальными данными, поэтому такую картинку не стоит использовать как надёжное количественное свидетельство.

Файлов отдельного автоматического test suite в рассмотренной структуре не найдено. `testing.ipynb` — визуальный анализ данных, а `scripts/test_*.sh` — оценка экспериментов, не unit tests.

## 17. Практический маршрут для нового исследования

1. Выберите фиксированный HD-эталон и загрузите его через `from_pretrained`.

3. Получайте для обучения независимые маргиналы; эталонные пары держите для оценки, если постановка предполагает обучение без пар.

7. Сравните с baseline-ноутбуком и готовыми методами на той же версии эталона и тех же правилах оценки.
8. Сохраняйте конфигурацию, seed, checkpoint, версию кода, Hub revision и параметры метрик. Для независимой финальной оценки создайте отдельный протокол test split: текущий конвейер его не выделяет.
